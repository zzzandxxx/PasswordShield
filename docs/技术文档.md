# 密码盾 技术文档

> v1.0.0 · 纯 Java · 零第三方依赖 · 单 Activity

## 1. 设计目标

在「个人自用」场景下做一个**可审计**的密码管理器：全部加密逻辑约 200 行、只使用 Android/JDK 内置 API，任何人可以在半小时内读完全部安全相关代码——这是"零依赖"的核心理由：不引入信任，只依赖平台。

不申请 `INTERNET` 权限（见 AndroidManifest.xml），从系统层面杜绝数据外传的可能。

## 2. 加密体系（Crypto.java）

### 2.1 密钥派生

```
主密码 + 16字节随机盐 --PBKDF2-HMAC-SHA256(250,000次, 256bit)--> AES 密钥
```

- 25 万次迭代：单次派生约 100–200ms（中端手机），暴力尝试成本被放大 25 万倍
- 盐随机生成且创建/改密时更换：相同主密码也得到不同密钥，防彩虹表
- 迭代次数写入备份记录（`iter` 字段），未来提升强度可平滑迁移

### 2.2 加密

- 算法：AES-256-GCM（`AES/GCM/NoPadding`），认证标签 128 位
- IV：12 字节，**每次保存全新随机**（GCM 下复用 IV 是灾难性的，这里从源头避免）
- 认证加密的意义：错误密码或被篡改的密文在解密时直接抛 `AEADBadTagException`，不存在"解出乱码"的中间态

### 2.3 已验证的测试（桌面 JVM 全流程实测）

| 场景 | 结果 |
|---|---|
| 正确主密码解密 | ✓ 完整还原 |
| 错误主密码 | ✓ GCM 认证拒绝 |
| 密文翻转 1 字节 | ✓ 解密失败 |
| 更换主密码后 | ✓ 新密码可用、旧密码失效 |
| 同明文两次加密 | ✓ 密文不同（随机 IV 生效） |
| 导出→导入往返 | ✓ 解密结果一致 |

## 3. 密码生成（PwGen.java）

- 随机源：`java.security.SecureRandom`
- **拒绝采样**取 `[0, bound)` 均匀整数：丢弃 `>= (2^32/bound)*bound` 的值，消除模偏差
- 组成约束：每类选中的字符集保证至少出现 1 个（先各取其一），再从并集池补齐
- Fisher-Yates 洗牌（同样拒绝采样取下标）打乱"必出现字符"在前缀的痕迹
- 强度估算：按密码实际覆盖的字符类算池大小（26+26+10+32），熵 = `len × log2(pool)`；四档：<40 弱、<60 中、<80 强、≥80 极强

## 4. 密码库（VaultStore.java）

- **整库加密**模型：内存中持有解密条目，任何写操作（增删改/改密）后整体重新加密落盘——简单且无条目级密文泄漏面
- 条目字段：id(UUID)/title/username/password/url/notes/createdAt/updatedAt，JSON 序列化后加密
- 单条损坏（JSON 解析失败）只跳过该条，不毁全库
- `lock()`：置空密钥引用 + 清空条目列表

## 5. 自动锁定与生命周期

- `Handler.postDelayed` 定时，任何用户交互（`onUserInteraction`）重置计时
- 可选 `onStop()` 时立即锁定（切后台/跳转其他 App）
- 锁定时同时 dismiss 打开中的对话框，防止后台截图泄密

## 6. 构建（build-apk.sh）

不依赖 Gradle 的 7 步直链构建，适合阅读与审计：

```
aapt2 compile/link（资源 + R.java，注入 package/versionCode）
  → javac -bootclasspath android.jar + core-lambda-stubs.jar
  → d8 --release --min-api 26（dex，用 build-tools 30 的 jar 版以兼容 JDK8）
  → jar 合并 dex → zipalign 4 字节对齐
  → 首次自动 keytool 生成自签 keystore → apksigner v1+v2 签名
```

## 7. 已知边界（如实说明）

- 未做键盘嗅探/无障碍劫持等运行时防护（依赖系统沙箱）
- 未用 AndroidKeyStore 硬件级保存密钥——密钥由主密码派生而非存于设备，这是"主密码可在任意设备解锁备份"设计的必然取舍
- 无自动化 instrumented 测试；核心逻辑通过桌面 JVM 等价测试覆盖（见 §2.3）
